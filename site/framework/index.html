Framework & Official Crates (Not nshm)

Reference index of all 19 official crates maintained inside longbridge/nsh at version 0.7.1—explaining their architectural roles across Apple, Android, Windows, Linux, Web, GPUI, and TUI targets and why none install via nsh add.

Section Overview

Developers auditing nsh-core reverse dependencies on crates.io (107 raw crates returned, 18 official framework crates) frequently mistake the 19 official longbridge/nsh crates for installable nshm modules. Every crate listed in this section is strictly **not** an nshm: running nsh add nsh-core or nsh add nsh-base fails immediately on nsh 0.7.1 with no #[native_module("...")] at the crate's root.

In Native Shell 0.7.1, the nsh CLI automatically manages and links these 19 Apache-2.0 crates when building host targets for TypeScript TSX or Rust applications. Rust-first applications and nshm library authors declare crates such as nsh-core, nsh-base, nsh-i18n, or nsh-testing directly in Cargo.toml via Cargo (cargo add nsh-core) rather than inside nsh.json dependencies.

Why `nsh add` Rejects All 19 Official Framework Crates

Inside crates/nsh-cli/src/nshm/manifest.rs, Manifest::read accepts a package only when it provides a Rust [lib] exporting #[native_module("<specifier>")], a Cargo.toml-free nsh.json with "exports", or a nsh.json declaring "platform" alongside a nsh-platform-<target> binary. Core libraries such as nsh-core (0.7.1) and nsh-base (0.7.1) supply Rust traits, reactive signals, layout shadow trees, and unstyled UI behavior instead of JS/TSX module bridges, while the 8 official platform backends compile directly through the CLI host pipeline rather than external "platform" manifests like nsh-platform-harmonyos.

Common Misconceptions When Reading crates.io Search Results

Do not confuse nsh-base (0.7.1) with an installable UI theme

nsh-base supplies unstyled focus, keyboard navigation, dialogs, code editor, and accessibility primitives (nsh/base) consumed by UI libraries like nsh-omarchy and nsh-shadcn, plus Cargo features (plot, editor, term, math). TSX apps access nsh/base directly from the framework rather than nsh add nsh-base.

Official platform crates vs community "platform" nshms

All 8 official nsh-platform-* crates (macos, ios, android, windows, linux, web, gpui, tui) ship inside longbridge/nsh. Only external targets built on Native Shell extension points—such as nsh-platform-harmonyos (0.1.1)—declare "platform" in nsh.json and install via nsh add.

Why nsh-extra (0.7.1) lives in /nshm/ instead of /framework/

Even though nsh-extra lives inside longbridge/nsh alongside these 19 crates, crates/nsh-extra/src/lib.rs explicitly defines #[native_module("nsh-extra")] so apps opt into camera, location, photos, push, and speech via nsh add nsh-extra --features ....
