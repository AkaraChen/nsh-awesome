板块概述

nsh.dev 官方文档（CC-BY-4.0）定义了 nsh 0.7.1 的核心规范、命令行语义与跨端架构；Awesome NSH 则在生态检索层面补充了跨 crates.io（119 个 crate）与 GitHub（89 个仓库）的六渠道扫描、官方框架 crate 隔离与 CI 实测 nsh add 验证。

为了避免把 7 条外部参考链接平铺成简单清单，本页面按开发者上手与模块发布流程将其组织为渐进式学习路径，并标注出每篇官方规范对应的站内实操入口与源码避坑要点。

`nsh.dev` 官方文档与 Awesome NSH 的互补定位

nsh.dev/docs/* 详述运行时架构、nsh.json 字段与 #[native_module] 语法，nsh.dev/directory 展示来自 longbridge/nsh-showcases 的 10 项精选；本目录站则逐条实测 nsh 0.7.1 兼容状态，明确剔除 19 个不可 nsh add 的官方框架 crate（NOT nshm），说明为何 6 个模块需通过 GitHub 或 Git --rev 安装，并开放 index.json 机器索引。

发布自己的 nshm 前：结合阅读 nshm Guide 与 /zh/discovery/

参考 nsh.dev/docs/nshm 编写清单后，再对照本站“发现机制”页避开 nsh-cli 0.7.1 实测陷阱：Cargo 虚拟工作区根目录报缺 [package] name、nsh.json 忘写 "exports"，或 0.6 依赖被 cargo publish 改写成子表后误绕过版本校验。

开发自定义目标后端前：结合阅读 Platform Extensions Guide 与鸿蒙后端详情

nsh-platform-harmonyos（0.1.1）是目前最完整的公开社区 "platform" nshm 实例，可直观印证 nsh.json "platform": "harmonyos"、[[bin]] 宿主程序与 [package.metadata.nsh.harmonyos] 元数据合并机制。
