板块概述

并非 crates.io 上所有带 nsh- 前缀或 keywords = ["nshm"] 标签的包都能被 nsh add 安装。根据 longbridge/nsh 源码中的清单解析逻辑（crates/nsh-cli/src/nshm/manifest.rs），只有满足 Rust（#[native_module("...")]）、纯 TSX（nsh.json "exports"）、混合型（两者兼备）或平台型（"platform": "<target>"）四种结构规则之一，且通过 nsh 0.7.1 语义化版本校验的包，才属于合法的可安装 nshm。

本专题页汇总了 13 个干净兼容 nsh 0.7.1 的模块，涵盖 crates.io（7 个主模块及归并的 40 个图标包子 crate）、github:owner/repo（5 个）与 Git 分支指定（1 个）。18 个仅因 Cargo 发布时将依赖改写为 [dependencies.nsh-core] 子表而绕过解析器的 0.6 旧包未在此列，相关详情集中记录于“发现机制”专题页。

图标子包归并规则与 GitHub 来源背景

为避免目录页被 40 个图标子 crate 重复刷屏，nsh-icon 的 5 个图标集 crate 与 supernsh-icons 的 35 个 Iconify 子 crate 均收纳在各自详情页中集中列出。此外，nsh-widgets 与 nsh-platform-harmonyos 当前须通过 GitHub 源安装（分别使用 --rev master 与 github:huacnlee/nsh-platform-harmonyos），以避开 crates.io 上锁定 ^0.6 或缺少 "platform" 字段的旧版问题。

同类模块选型建议

UI 组件库选型：nsh-omarchy vs nsh-shadcn

若追求已有 0.2.0 发布与使用积累、系统主题自动切换与图表组件内置，nsh-omarchy 更稳妥；nsh-shadcn 仍处于早期 0.1.0 阶段（Navigation Menu 与 Sidebar 尚有部分缺口），仅在明确偏好 new-york-v4 类名习惯或需要内置 Chat 对话组件时作为早期尝鲜对比选项。

图标方案选型：nsh-icon vs supernsh-icons

常规应用仅需 5 套主流单色矢量图标且希望最小化依赖体积时，优先 nsh-icon；当项目需要品牌彩色 Logo、国旗、260 套 Iconify 图标或 .ttf 图标字体时选用 supernsh-icons（注意其 Web 打包需准备 LLVM clang 与 llvm-ar）。

图形与可视化选型：Canvas 套件 vs GPU 底层接口

业务图表与网络拓扑优先使用 nsh-graph 与 nsh-o11y；需要自定义 3D/计算着色器且跨端运行选用 nsh-webgpu；而熟悉 react-native-skia 声明式 2D 滤镜且主要面向 macOS 与 Linux 桌面 GPU 时可考虑 nsh-skia。
